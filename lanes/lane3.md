- **All lanes, the Storm containers (stpl.h): how the Storm lists went, for your own D2Storm…Strc list views.** On main after smem-c: `TSLink<T>` (with Storm's destructor and `Prev`), `TSLinkedNode<T>` (a node's `m_link`), `TSList<T>` (constructor, `Head`, `Link`, `LinkNode`, `Next`, `RawNext`, `UnlinkNode`, `NewNode`, `UnlinkAll`, `DeleteNode`, `Clear`), and SMemAlloc/SMemFree as C functions. The recipe that kept every unit equal:
  - The record derives from `TSLinkedNode<T>` (its link at offset 0 is `m_link`); drop hand-written link zeroing in its constructor and `Unlink()` at the end of its destructor. If that destructor gains an unwind state the original doesn't have, the record's destructor calls something that may throw: with SMemFree a C function that usually goes away.
  - A statically constructed list is a plain definition in the file that uses it, `TSList<T> gList; // 0xVA`, with `// build: symbol ??__EgList@@YAXXZ 0x…` and `??__FgList@@YAXXZ 0x…` for its dynamic initializer and atexit destructor (the compiler puts the link offset and the terminator's back link in .data itself and only stores the complemented terminator address at run time). Drop the plan's 4-byte terminator record and the placeholder's init/destroy pair.
  - Template members the original has at fixed addresses get `// build: symbol` lines with their decorated names (`?LinkNode@?$TSList@UT@@U?$TSGetLink@UT@@@@@@QAEXPAUT@@I0@Z` and so on; SERR.CPP lists a full set). Out-of-class members (UnlinkAll, DeleteNode, Clear, RawNext) are emitted only where used; an explicit `template` line covers one the original has but nothing calls.
  - `STORM_TYPENAME(T)` gives the allocator its file name from the compiler's own type descriptor: map `??_R0?AUT@@@8` to its address and drop the plan's name records that cover it (watch for records that run into it: they lose the overlap and get dropped whole).
  - Where code starts at the head and tests `(int)p > 0`, the original keeps the head in a variable first (`T* pHead = list.Head(); for (T* p = pHead; (int)p > 0; p = p->m_link.m_next)`).
  - The type-count effect (lane 1's finding) bites here too: if one unrelated function swaps two registers after a conversion, count the type definitions (anonymous unions count) before trying anything else.
  - Since stpl-members and logmsg-list: stpl.h defines UnlinkAll, DeleteNode and Clear itself (drop your file's copies), and TSLinkedNode's destructor unlinks (Fog's /EHa code shows both unlinks; without exception handling the second folds away). In a /Ob2 or /EHa module (Fog), more of the in-class members come out-of-line with unwind states; map each one the original has by symbol line, and list the ones nothing calls as explicit instantiations. Watch the type descriptor's 8-byte header: a plan record that runs into it is dropped whole (gszLogPrefix had to end at 0x70811C).
  - An unreferenced stand-in that is a template member for one of several list types in the file (SFILE.CPP has five) can only be placed by its neighbours: members come out grouped per type, so a stand-in directly in front of a type's LinkNode is that type's. Where nothing ties one to a type, leave it.
