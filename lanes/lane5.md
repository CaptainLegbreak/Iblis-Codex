## Notes for other lanes

- All lanes (object order evidence): each object that asserts has its own source-path string in .rdata (.\GAME\Clients.cpp, d:\diablo2\...\a5q1.cpp, ...), and those strings run in link order. Together with code order they count the objects inside a run of back-to-back language copies (no-data objects), e.g. D2Game's 0x7312E0-0x731448 = Clients, Level, SCmd, CCmd, Arena, Party, Event.
- All lanes (placement): a function can compile differently when a global it uses is defined in the same object (the plan's definition travels with the file). When a stray built equal in its placeholder but not in its file, check whether the placeholder defines data it reads; move that definition too (Game_0052C170's gwGameId, the rare rolls' gnRareAffixCounts).
- All lanes (how the compiler lays out one object's .data; checked against five D2Game objects, no exceptions): it takes definitions in order, but when the next one would need alignment padding (a big table wanting 8 at a 4-mod-8 offset), it first places the earliest later definition that needs no padding there, of any size, and only then the big one. E.g. AiThink.cpp: copy (60 B), then gaszLanguageNames_0073D478 (60 B, defined last) before gaAiTable; a5q2.cpp: runes (12 B), then a 28 B table defined after the messages, then the messages. So a 4-byte zero gap inside an object means nothing later in that object fits there without padding, and a small table that the image has after a big one cannot belong to an object where it could have filled an earlier gap. Statics defined before the data include come out before it (definition order).
- All lanes (alignment rule, useful for finding object boundaries): the compiler aligns large data objects to 8, and the image agrees: of the planned named records of 64 B or more, 263 start on an 8-byte boundary and 12 don't. An object whose data holds such a record is itself 8-aligned, so it can only start on an 8-byte boundary. Two uses: (1) a big planned record at 4 mod 8 is really more than one object, e.g. gNpcConfig = a count + an 8-aligned array (lane5/npc-config); the other 11 are gaszErrorTypeNames, gaModeTable (Fog ErrorManager.cpp), gtInterface (ChatDlg.cpp), gaActions (CmdTbl.cpp), gaSkillTabX (Unknown_004AA9C0.cpp), gtQuestTextsSevenTombs/FallenAngel/Siege (text.cpp), gaTextEntries (Unknown_004A6460.cpp), gapLevelSpeeches (UnitSnd.cpp), gszTypeNameStringEntryList_007... (Ignorelist.cpp).
